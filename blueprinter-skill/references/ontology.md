# Blueprint JSON format

This is the authoritative schema for `*.blueprint.json`. It is byte-compatible with the Agent Blueprint Builder app's export/import format — a blueprint generated by this skill can be imported into the app (Import button) for interactive editing, and vice versa.

## Top-level wrapper

```json
{
  "version": "1.0",
  "exportedAt": "2026-07-06T00:00:00.000Z",
  "blueprint": { ...Blueprint }
}
```

## Blueprint

```json
{
  "id": "<uuid>",
  "title": "string",
  "description": "string — 1-3 sentences on what the process does",
  "clientName": "string",
  "projectName": "string",
  "impactedAudiences": ["string"],
  "businessBenefits": ["string"],
  "clientContacts": ["string"],
  "createdBy": "string",
  "lastModifiedBy": "string",
  "lastModifiedDate": "ISO timestamp",
  "version": "1.0",
  "status": "Draft | In Review | Approved | Archived",
  "changeLog": [{"id": "<uuid>", "timestamp": "ISO", "author": "string", "description": "string"}],
  "nodes": [ ...SerializedNode ],
  "edges": [ ...Edge ],
  "comments": [],
  "parkingLot": []
}
```

## SerializedNode

```json
{
  "id": "unique-string (kebab-case slugs are fine, e.g. 'invoice-triage')",
  "type": "<same value as data.nodeType>",
  "position": {"x": 0, "y": 0},
  "data": { ...node data, see below }
}
```

Positions may be left at `{x: 0, y: 0}` — the renderer auto-layouts, and the app re-layouts on import if needed. `type` MUST equal `data.nodeType`.

## Edge

```json
{
  "id": "unique-string",
  "source": "node-id",
  "target": "node-id",
  "sourceHandle": "condition/route/branch id — REQUIRED when the source is a decision, router, or parallel split; omit otherwise",
  "data": {"conditionLabel": "optional label shown on the edge", "description": ""}
}
```

## Common data fields (all node types)

Every `data` object has `nodeType` and `name`. Optionally: `ai_generated: true`, `ai_confidence: "high"|"medium"|"low"`, `ai_notes: "string"` — always set these on nodes you inferred rather than were told.

`IOItem` = `{"name": "string", "required": true|false}`.

## Agent spec fields (work-agent, orchestrator, agentLoop, evaluatorOptimizer)

Optional on all agent-type nodes; fill them in whenever known — they are the engineering handoff:

```json
{
  "description": "routing contract: what it does + when to use it + how it differs from sibling agents",
  "skills": ["string"],
  "tools": ["string"],
  "autonomyLevel": "strict | guided | open",
  "guardrails": ["hard constraint the agent must never violate"],
  "successCriteria": ["verifiable check that proves the goal was met"],
  "stopCondition": "when the agent stops",
  "failureHandling": "what happens when it fails",
  "hitl": {
    "mode": "none | notify | sampled | approval",
    "reviewer": "role or person",
    "sla": "e.g. 4 business hours",
    "samplingRate": "e.g. 10% of outputs (sampled mode)",
    "escalationPath": "what happens on timeout/rejection"
  }
}
```

Any node whose action is hard to reverse or outward-facing (sending to customers, moving money, deleting records, filings) MUST have `hitl.mode: "approval"` with a reviewer.

## Node data schemas by type

### trigger
```json
{"nodeType": "trigger", "name": "", "triggerType": "event | scheduled | manual", "description": "", "configuration": ""}
```

### work (agent | automation | human)
```json
{"nodeType": "work", "name": "", "workerType": "agent | automation | human", "goal": "",
 "inputs": [IOItem], "tasks": ["string"], "outputs": [IOItem],
 "integrations": ["string" or {"name": "", "action": "", "inputs": [], "outputs": [], "apiEndpoints": [{"id": "", "url": "", "method": "GET"}]}]}
```
Plus agent spec fields when `workerType` is `agent`. `goal` is required.

### decision (rule-based branching)
```json
{"nodeType": "decision", "name": "", "description": "",
 "conditions": [{"id": "cond-approved", "label": "Approved", "description": ""}]}
```
One outgoing edge per condition, with `sourceHandle` = the condition `id`.

### router (model-driven classification)
```json
{"nodeType": "router", "name": "", "description": "", "classifierInstructions": "",
 "routes": [{"id": "route-simple", "label": "Simple", "description": "what belongs on this route"}],
 "fallbackRoute": "label of the route for low-confidence items"}
```
One outgoing edge per route, `sourceHandle` = route `id`. Route descriptions must be mutually exclusive — the classifier reads them.

### parallel (split or join)
```json
{"nodeType": "parallel", "name": "", "mode": "split | join", "description": "",
 "branches": [{"id": "branch-a", "label": "Branch A", "description": ""}],
 "joinBehavior": "wait-all | wait-any | merge-results"}
```
Split: one outgoing edge per branch (`sourceHandle` = branch id); `branches` only used in split mode. Join: `joinBehavior` only; every split needs a downstream join.

### orchestrator (manager + dynamic worker pool)
```json
{"nodeType": "orchestrator", "name": "", "goal": "",
 "delegationStrategy": "how the manager decomposes and assigns work",
 "workers": [{"id": "worker-x", "name": "", "description": "what it handles and when to pick it", "skills": ["string"]}],
 "synthesis": "how worker outputs combine",
 "terminationCondition": "REQUIRED — when the manager stops",
 "maxIterations": "e.g. 10 rounds", "budget": "e.g. $5/run",
 "inputs": [IOItem], "outputs": [IOItem]}
```
Workers live INSIDE the node (not as separate canvas nodes) because the manager invokes them dynamically at runtime.

### agentLoop (one autonomous agent with skills/tools)
```json
{"nodeType": "agentLoop", "name": "", "goal": "",
 "inputs": [IOItem], "outputs": [IOItem],
 "maxIterations": "e.g. 25 steps", "memory": "context kept across iterations",
 "integrations": ["string"], "skills": ["string"], "tools": ["string"],
 "stopCondition": "REQUIRED — when the agent stops"}
```

### evaluatorOptimizer (generate → score → iterate)
```json
{"nodeType": "evaluatorOptimizer", "name": "", "goal": "",
 "generatorDescription": "what produces the candidate output",
 "evaluatorCriteria": ["verifiable check"], "passCondition": "e.g. all criteria met",
 "maxIterations": "e.g. 5 rounds", "onMaxIterations": "e.g. escalate to human review",
 "inputs": [IOItem], "outputs": [IOItem]}
```

### workflow (reference to another blueprint)
```json
{"nodeType": "workflow", "name": "", "description": "", "workflowId": "", "workflowName": "",
 "inputs": [IOItem], "outputs": [IOItem], "version": "1.0"}
```

### end
```json
{"nodeType": "end", "name": "", "description": "", "outcome": "what reaching this state means"}
```

## Structural rules (the renderer validates these)

1. Exactly one or more trigger nodes; at least one end node.
2. Every non-trigger node has ≥1 incoming edge; every non-end node has ≥1 outgoing edge.
3. Work nodes have a goal (E004). Orchestrators have a termination condition (E006). Agent loops have a stop condition (E007).
4. Decision/router: ≥2 conditions/routes, one edge per condition/route via `sourceHandle`.
5. Every parallel split has a matching join downstream (W009).
6. Edge `source`/`target` must reference existing node ids.
